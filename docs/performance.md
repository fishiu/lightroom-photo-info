# 性能与缓存

缓存主要减少重复查询和解码；自动更新仍由当前照片状态驱动。这里记录一次开发期间的测量，帮助理解优化的实际范围。

## 测量结果

在同一台 Mac、同一 Lightroom 9.6 图库中，以优化编译比较加入缓存前后的实现。重复查询同一张 GR4 样片 100 次；新建 `MetadataStore` 后首次查询各采样 10 次。

| 操作 | 缓存前中位 | 缓存后中位 | 缓存前 P95 | 缓存后 P95 |
| --- | ---: | ---: | ---: | ---: |
| 已打开库中的重复元数据查询 | 1.485 ms | 0.0114 ms | 1.673 ms | 0.0142 ms |
| 新建 MetadataStore 后首次查询 | 3.186 ms | 3.323 ms | 6.772 ms | 52.206 ms |

这些查询全部只读，未清空系统磁盘缓存。首次查询包括库发现和打开连接，不等于真正冷盘读取；样本较少，P95 也会受到单次波动影响。结果不代表修图渲染耗时或整机 CPU 的改善倍数。

另一组四张照片循环读取的交叉检查中，热读中位数从 1.606 ms 降到 0.0113 ms；120 次循环只解码五份文档，其中一张照片对应两份参数相同的候选。缓存没有改善首次库发现，主要收益来自重复读取。

## 前台刷新与切图

界面状态读取在上述样本中约为 6 ms，高于已缓存的元数据查询。当前前台每 100 ms 观察一次界面；停在同一照片时，元数据每秒校验一次。选图、相册或 Cloud / Local 来源变化立即触发查询，查询后再次核对当前选择，防止晚返回的结果覆盖新照片。

模拟 100 次静止照片检查时，元数据查询从 100 次降到 10 次。应用切到后台、手动隐藏或会话停用后，通过 `NSWorkspace` 通知停止常规轮询。

新参数就绪前保留整组快照，文件名和参数一起更新。超过 150 ms 时标记“显示上次读数”；超过 1.2 秒仍未成功则清除旧参数并保留面板外壳。已确认的网格、比较视图或窗口隐藏状态会正常隐藏浮窗。临时 Accessibility 失败不会立即触发整窗隐藏。

这些策略用于减少闪动和错配，不保证任何负载下都没有等待。

## 缓存正确性

- 解析缓存按完整文件名和相册范围区分，`wfindex` 的 `PRAGMA data_version` 改变后失效。最多 256 项，异常大的候选集合不缓存。
- 展示字段缓存按图库、docID、assetID、文件名和 winning revision 匹配，并检查 `mcat` 的 `data_version`。最多 256 份，估算字段成本上限为 2 MiB；不缓存原片或原始 MessagePack 文档。
- 查询前后校验两库版本，途中有外部提交时不发布混合版本结果。同 revision 的内容修改也会触发保守失效。
- 缓存不绕过同名冲突和相册成员检查。正常前台轮询中，停留在同一照片时约每秒检查外部变更。

测试覆盖热读不重复解码、外部新 revision、同 revision 修改、相册成员变化、重命名、新增同名冲突、缓存容量和禁用缓存模式。刷新测试覆盖静止照片、换片、换相册和来源切换。

## 为什么暂未加入块预读

样本中热读约为 0.01 ms，未缓存的已打开库查询通常为 1–2 ms。当前没有可靠的胶片栏排序接口，按数据库行号或文件名猜测“下一张”可能浪费 I/O，并挤占当前选图的读取。

如果后续测量确认未缓存切图成为瓶颈，并能可靠取得显示顺序，再考虑小批量、可取消的低优先级预读。

## 测量当前版本

[Tools/Benchmark.swift](../Tools/Benchmark.swift) 在同一进程内测量选择读取、新建 store 和热读，并输出缓存统计与模拟刷新次数。在仓库根目录执行：

```sh
mkdir -p build
xcrun swiftc -O -D OPTIMIZED \
  Sources/LightroomSelection.swift Sources/MetadataRefreshSchedule.swift \
  Sources/MetadataStore.swift Sources/MessagePack.swift \
  Tools/Benchmark.swift -lsqlite3 -o build/metadata-benchmark
./build/metadata-benchmark
```

测量选择读取时，保持 Lightroom 位于前台并打开单张云端照片，终端进程需要对应的辅助功能权限。锁屏、网格模式或权限不足的读取不计入有效界面样本；`valid_selection_reads` 应等于 40，才能解释选择读取结果。

输出可能包含当前文件名、相册名和前台应用标识。对外分享前请脱敏。历史表格的无缓存基线属于早期开发版本；当前命令用于测量当前代码，不会自动重建该历史基线。比较不同版本时，应固定相同机器、图库、前台状态和采样方法。
